## 规则

用 `wc -l` 判定。等于 320 不过硬线。大于 320 才过硬线。

| 档 | 条件 | 动作 |
|----|------|------|
| 设计目标 | 新的非测试源文件 | 以 200 行为目标 |
| 未过硬线 | `wc -l` ≤ 320 | 超过 200 行也不算违规，不强制拆 |
| 硬线 | 非测试源文件 `wc -l` > 320，且多个职责混在一个文件里 | 必须按现有架构拆开。原模块继续导出测试和外部还在用的符号 |
| 测试硬线 | 测试文件 `wc -l` > 320 | 与非测试同一条硬线。当前没有测试超过 |
| 属性测试 | 长度来自用例表 | 不为贴近 200 行设计目标而拆 |
| 下一档 | `src/lib/workshop/canvasEngine.ts`（285），以及其余 `wc -l` ≤ 320 的文件 | 不拆 |
| 强耦合状态机 | 单一状态机、没有测试、又强耦合 | 不硬拆。记入本文「清理记录」 |

未同时满足「过硬线」和「多职责」的，不拆。

## 例外

超过硬线也不拆：

- 生成代码
- SQL migration
- vendored 第三方代码
- 提示词
- 纯数据（名录、GeoJSON、种子 JSON）
- 书面豁免
